# Report contract

输出不是"写一份好看的东西"，是让下一个人能核对。固定结构的作用只有一个：
**让"查过/没查过"可被外部检验**。

本文件替代 `SKILL.md` §5 里的 13 行样例。样例仍然成立，只是不再完整。

## 规则（先看这四条）

1. **计数必须加总**。`C`（候选）总数 = `GO` + `HOLD-evidence` + `HOLD-capability` + `KILL` + `未判`。
   加不上就是漏账，必须在报告里显式写出差额。
2. **每个 `path:line` 在写进报告前单独回读一次**。区间引用要核首末两行。
   凭 grep 印象写的行号是本 skill 已犯过 7 次的错误。
3. **`L3-repro` 与 `L3-lit` 不许混写**。"上游已证实"和"我打通了"是两个量级。
   报告元数据里的 `L3-repro` 计数只能来自本目录的 `EV-###` 记录。
4. **任何动态动作必须声明授权来源**。谁批的、在哪个主机、有无回滚路径。
   没有这三项的 L3 不出现在报告里，只出现在 `GAP-###`。

## 两种规模，两套结构

| 情况 | 用哪套 |
|---|---|
| 单点问题（"这个函数能不能注入"）、项目 < 200 个 Go 文件、≤ 30 分钟 | **简版**：一段结论 + 一张候选表 + 一句覆盖边界 |
| 完整项目审计、给了多相目标、要交给别人复核 | **完整版**：下面 8 节，不得省略 |

不要对 5 分钟的问题套 8 节模板——那会让"覆盖度"变成凑数的形式主义。

---

## 简版

```markdown
**结论**：<一句话，带证据等级>
**目标**：<repo> @ <commit 或 "tarball, commit unknown">，扫描 <N> 个 .go 文件
**候选**：<C-###> `<rule_id>` `path:line` — <裁决 + 一句闸门>

**覆盖边界**：<跳过的树、未判的 Tier、未查的闸门>
```

## 完整版（8 节）

```markdown
# <project> — Go RCE 审计报告

- 目标 / 源码根：{repo 与审计路径}
- 版本 / revision：{commit 或 "tarball, commit unknown"；Go 版本}
- 审计日期：{YYYY-MM-DD HH:MM 时区}
- 请求范围：{目录、相（E1–E6/X）、明确排除项}
- 分析模式：{static | static + 授权动态验证（授权来源：…）}
- 覆盖度：{full | partial}（不是"安全"的声明）
- 结果计数：GO {n} / HOLD-evidence {n} / HOLD-capability {n} / KILL {n} / 未判 {n}
- 证据等级：L3-repro {n} / L3-lit {n} / L2 {n} / L1 {n} / L0 {n}
- 扫描基线：{规则数} 条规则，{命中数} 命中，{LOC}k 行，命中率 {x}/千行

## 1. 目标与执行面

{这是什么程序；哪些可执行体；从 main 到 listener / 任务消费的启动路径}

| App | 角色 | 入口 | 监听 / 目标 | 协议 / 身份 | 证据 |
|---|---|---|---|---|---|

{监听值必须写清来源：字面量 / 默认 / 配置 / 环境变量 / 未解析}

## 2. 信任边界与执行原语

{谁能触发什么执行；在哪一行把"输入"变成"可执行语义"}

| 主体 | 达到执行原语需要的权限 | 边界证据 | 谁在守 |
|---|---|---|---|

{如果执行原语是产品设计（CI 流水线、面板运维、备份工具），**必须明说**
"这是设计行为"，并写出守它的那道闸门；写不出闸门就是 HOLD，不是 KILL}

## 3. 候选清单（全量，含已否决）

| ID | Tier | rule_id | 位置 | 函数 | 入口可达 | 调用链 | 状态 |
|---|---|---|---|---|---|---|---|
| C-001 | S | E1-SHELL-EXPR | `pkg/x/run.go:60` | `execCommands` | 是（EP-12） | 2 跳 | 已裁决 |
| C-002 | B | E4-HOOK-WRITE | `pkg/y/hook.go:41` | `writeHook` | 否 | — | KILL |

**这张表要覆盖扫描器的全部命中，或明确写"只列 S/A 档，B/C/X 共 N 条未判（GAP-002）"。**

## 4. 裁决

每条一行，`GO` / `HOLD-evidence` / `HOLD-capability` / `KILL` 四选一，**不许写"再看看"**。

| ID | 裁决 | 理由（含闸门 `path:line`，或"未查到"）|
|---|---|---|
| C-001 | KILL | 脚本内容是常量：`run.go:180` |
| C-003 | HOLD-evidence | 缺 `checkName` 白名单验证，未读到该 controller 的校验层 |

- `HOLD-capability`：能执行，但这是产品提供的执行能力，缺的是**策略声明**而不是代码缺陷
- `HOLD-evidence`：缺一条关键证据（闸门没查到 / 依赖没读到），**不得**升级为漏洞
- `KILL` 必须给闸门位置；给不出位置的 KILL 是 `HOLD-evidence`

## 5. 已复现（L3-repro）

没有就不写这一节，并在 §7 写"动态验证未执行"。

### EV-001 — {一句话，例如"未授权任意文件读"}

- 目标：{版本} @ {主机}，授权来源：{谁批的}，回滚路径：{如何还原}
- 触发命令：{完整可复制}
- 期望 / 实际：{字节数、响应码、文件内容摘要}
- **负样本对照**：{同一请求把 payload 改成无害值时的结果}——缺这一行，L3 无效
- 残余影响：{写到哪、读到什么、有没有副作用}
- **口径**：{如果上游 writeup 说 RCE 而实测不是，把偏差写在这里。别信靶场目录名}

## 6. 覆盖与盲区

| 范围 | 状态 | 已看 | 结论 / 缺口 |
|---|---|---|---|
| E1 shell 拼接 | reviewed | 全部 `exec.*` 调用 | 2 命中，均 KILL |
| E3 反序列化 | partial | `encoding/gob` 用法 | 未追数据来源 |
| E4 写入即执行 | not-assessed | — | 本轮未请求 |
| vendor/ | not-applicable | — | 扫描器跳过 |

状态只有四种：`reviewed` / `partial` / `not-assessed` / `not-applicable`。
`not-assessed` **不是**"干净"，报告里必须能一眼分开。

缺口单独编号：

| ID | 缺口 | 为什么没做 | 补它需要什么 |
|---|---|---|---|
| GAP-001 | Tier C 共 72 条未逐条判 | 预算用尽 | 约 40 分钟人工 |
| GAP-002 | 无本地构建，L3 无法执行 | 无可编译环境 | 一次授权 + 一台能起服务的主机 |

## 7. 复现与限制

- 静态证据：{读过的树、跳过的树、行号回读方式}
- 动态验证：{执行了什么 / 未执行，为什么}
- 依赖获取：{有没有拉第三方源码，从哪拉，是否校验}
- 目标修改：{有没有动过目标文件（应当是没有）}
- 方法论限制：{单规则扫描的固有盲区，例如 argv 跨函数组装}

## 8. 修复与回归

| 优先级 | 对应 ID | 动作 | 回归判据 | 状态 |
|---|---|---|---|---|
| P1 | C-003 | 加 `DetailName` 白名单 + 单引号包裹 | 含 `'` 与 `;` 的名字被拒 | proposed |

"proposed" 与 "executed" 必须分开。没跑过的回归不能写成通过。

## 一致性检查（交付前逐条打勾）

- [ ] 候选总数 = 四种裁决之和 + 未判
- [ ] 每个 `path:line` 已单独回读，区间已核首末
- [ ] 每个 `KILL` 有闸门位置，每个 `HOLD` 写清缺哪一条证据
- [ ] `L3-repro` 计数 = `EV-###` 条目数，且每条有负样本对照
- [ ] `not-assessed` 与"reviewed 无发现"在报告里不混
- [ ] 没有把"扫描器跳过"写成"没有漏洞"
- [ ] 报告里没有留下 `<占位符>`
```
